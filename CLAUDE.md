# CLAUDE.md — сайт ИТ-обслуживания для малого и среднего бизнеса

## О проекте

Сайт компании, которая берёт на себя ИТ малого и среднего бизнеса в Санкт-Петербурге «под ключ»: абонентское обслуживание, серверы и инфраструктура, облака, кибербезопасность, 1С (администрирование), базовая автоматизация, аудит и консалтинг.

- Рабочее название бренда: `it-help` (финальное не выбрано — название бери из `src/config/site.ts`, не хардкодь в разметке).
- Аудитория: владельцы и директора SMB. Им важны стабильность, понятный язык и экономия на ИТ.
- Позиционирование: мы — отчаянные гики, которые дают клиенту спокойствие за его ИТ. Идея слогана: «вы платите за то, что мы всё предусмотрим».
- Цель сайта: заявка (форма), звонок или сообщение. Каждая страница ведёт к одному из этих действий.
- Сайт ведёт один человек, к SEO может подключаться SEO-специалист, который правит Markdown и метаданные.

## Стек

- Astro 6, статическая сборка (`output: 'static'`). Node 22.
- Перед написанием кода по Astro **всегда сверяйся с документацией через MCP `astro-docs`**, не полагайся на память: API менялся между версиями.
- Коллекции контента: только `src/content.config.ts` (не `src/content/config.ts` — это legacy и в Astro 6 не работает). У каждой коллекции обязателен `loader` (`glob()` / `file()` из `astro/loaders`). Zod импортируй из `astro/zod`.
- Клиентский JS — только там, где он нужен (острова). По умолчанию страницы без JS.
- Стили: обычный CSS с custom properties (дизайн-токены в `src/styles/tokens.css`). Без UI-фреймворков, без Tailwind, пока я явно не попрошу.
- Новые npm-зависимости — только после согласования со мной, с объяснением зачем.

## Структура

```
src/
  config/site.ts         # название, контакты, соцсети, реквизиты — единый источник
  content.config.ts      # коллекции и схемы
  content/
    services/            # страницы услуг (.md)
    cases/               # кейсы
    blog/                # статьи
  components/            # переиспользуемые блоки (ServiceCard, PriceBlock, CaseCard, LeadForm…)
  layouts/BaseLayout.astro  # <head>, мета, OG, JSON-LD, шапка, подвал
  pages/
  styles/
public/
  fonts/                 # шрифты только локально
```

## Коллекции и обязательные SEO-поля

У `services`, `cases`, `blog` в схеме обязательны: `title` (до 60 символов), `description` (120–160 символов), `ogImage`. Опционально: `h1` (если отличается от title), `noindex`, `updatedDate`. Для `services` дополнительно: `order`, `priceFrom` (число, рубли), `faq` (массив вопрос/ответ). Ограничения длины задавай в Zod-схеме, чтобы сборка падала при нарушении.

## Карта сайта

Главная · Услуги (по странице на услугу) · Тарифы · Кейсы · О компании · Блог · Контакты · Политика обработки персональных данных. Каждая страница услуги: проблема клиента → что делаем → как работаем → стоимость «от» → кейс → FAQ → форма. На страницах услуг и FAQ генерируй JSON-LD (`Service`, `FAQPage`), на главной — `LocalBusiness`.

## Тексты

- Язык сайта — русский. Пиши для директора, а не для админа: без жаргона, аббревиатуры расшифровывай.
- Конкретика вместо общих слов: сроки реакции, что входит в обслуживание, цены «от».
- Не выдумывай кейсы, цифры, клиентов, отзывы и сертификаты. Где данных нет — ставь заметную заглушку `TODO:`.

## Дизайн

- Облик оригинальный, не шаблонный «синий корпоративный». Характер бренда — уверенные гики: спокойствие + технологичность.
- Mobile-first, доступность уровня WCAG 2.1 AA (контраст, фокус, alt, семантика).
- Картинки только через `astro:assets` (`<Image />`), с размерами и lazy-loading.

## Юридические и технические требования (РФ)

- 152-ФЗ: на каждой форме — отдельный чекбокс согласия на обработку ПДн со ссылкой на политику, по умолчанию не отмечен. Политика ПДн — отдельная страница.
- Никаких ресурсов с иностранных хостов: шрифты, скрипты, иконки — только локально. Никаких Google Fonts/Analytics/reCAPTCHA.
- Аналитика — только Яндекс.Метрика, ID из переменной окружения; если переменной нет — счётчик не выводится.
- Генерируй `sitemap.xml` и `robots.txt`.

## Форма заявки (этап 2, без моей команды не делать)

Заявка уходит в Zammad (создание тикета через API). Токен Zammad — только в серверной переменной окружения, **никогда** в клиентском коде и в репозитории. Защита от спама — honeypot + ограничение частоты, без внешних капч.
